RunMethod パラメータ & 軌跡プレビュー

実機と同じ src/RunMethod/EdgePidRunning.js を、仮想コース（白地に黒ライン）の上で走らせます。 Kp / Ki / Kd を動かすと軌跡と偏差の応答が変わります。

走行方式

シナリオ

シナリオを読み込みます…

本体シミュレータ（index.html）や画面なし走行（tools/headless-run）と同じ手順で流します。 読み込みは src/ScenarioJsonLoader.js、実行は Sorot / ScenarioControl / Navigator / RunControl をそのまま回します。区間の入り口の姿勢は前の区間の出口で 決まるので、1区間だけ見ていたときとは結果が変わります。
コース画像と組み合わせると、実際のコースの上で区間ごとの KP / KD を追い込めます。

本体と同じに走ることは、画面なし走行と突き合わせて確かめています。 2026/99_Lコース を コース画像4倍 / スポット10mm / Ts 0.01 / 本体と同じモータの模型 で流すと、37コマンドすべて同じ順に通り、SNO40/CNO1（ET相撲のリモート）まで届きます。

PID パラメータ（RunInfo）

微分項は1周期（10ms）差分なので、以前の「200ms前との差」だった頃より大きな Kd が要ります。 直線なら Kd 60 前後で整定が 6.0s から 2.0s に縮みます。Kd を 0 に戻すと振動が収まらなくなる様子が見られます。

目標反射光 = (黒 + 白) / 2 − (黒 − 白) × WPER / 100
→ 現在の目標値: 32.5

既定値は public/config/2026/robot.yaml の black_threshold / white_threshold と同じです。

仮想コース

コース画像を読み込みます…

コースの PDF はベクタなので、大きく描くほど本当に細かくなります。 ワールド座標（開始位置・ライン幅 4px・走行体の縮尺）は倍率を変えても動きません。
効くのは線の位置の正確さです。等倍では線の縁が 5mm に丸められ、 線として読む幅も釣り合い点も 1mm ほどずれます。実測（スタート直後の縦線を 0.1mm 刻みで横切って測定、スポット 10mm）:

倍率1画素線として読む幅左エッジの釣り合い点
等倍5mm20.9mm511.02
2倍2.5mm22.3mm511.02
4倍1.25mm20.5mm511.20
8倍0.63mm20.1mm511.24

実際の線幅は 20mm なので、4倍で十分近づき、8倍にしてもほとんど動きません。 8倍は読み込みが 0.5 秒ほどかかり、画素だけで 100MB 使います。
なお、反射光の滑らかさは倍率では変わりません。線の縁は本当に段差なので、 点で読む限りどれだけ細かくしても 32.5 の段差が出ます。滑らかさはスポット径の役目です。
倍率を変えるとゲインの意味も変わります。等倍の画像は線の縁が 5mm ぶんぼけていて 勾配がゆるく、細かくするほど勾配が立ちます。同じ Kp でも効きが強くなるので、 倍率を変えたら Kp を取り直してください（FWD 50 / α 5.0 / Ts 0.01 では 等倍 Kp 6 が、4倍では Kp 4 のほうがきれいに追従します）。

実機のカラーセンサーは点ではなく、直径 10mm ほどの範囲の平均を読みます。 ここを 0 にすると本体シミュレータとまったく同じ「真下の 2 画素」に なりますが、コース画像は 1px = 5mm しかないため反射光が 5mm 刻みの階段になり、 段の中では偏差が動きません。エッジ追従の比例帯が消えて 5mm 単位のオン・オフに なるので、舵が効かなくなります（直線でも 150mm ほど同じ値を読み続けます）。 既定の 10 は実機に合わせた値です。

本体シミュレータ（index.html）と同じコース画像・同じ画素の読み方 （sim/sensor-sampling.js）で走らせます。1px = 5mm、黒ラインは 4px です。 線の上の色つき区間や灰色の印も、本体と同じく線として読みます。 走り方も本体と同じくオドメトリの進みぶんで動かすので、 ここで合わせたゲインはそのままシナリオへ持っていけます。

走った距離と速さは軌跡の下に出ます。実機は FWD 50 でおよそ 240mm/s ですが、 既定のモータモデル（α 1.0）だと 54mm/s しか出ません。実機の速さで見るには α 5.0 / Ts 0.01 にしてください（268mm/s）。Ts は制御の周期でもあり、 0.04 のままだと 1 周期で 12mm 進んでしまい、幅 20mm の線をまたいで追従できません。 速さが変わると微分項の効きも変わるので、Kd は速さを決めてから合わせます。

走行体はライン幅 20mm を基準に実寸比（車輪間隔 125mm / 車輪径 55mm）で描いています。 既定の 12.0 はこの縮尺で車軸の 60mm 前方にあたります。実機（およそ 100mm 前方 = 20 前後）まで 伸ばすこともできますが、先読み距離が変わるため既定ゲインのままだと整定しなくなります。

形状によって必要なゲインが違うことを確かめられます。微分項を1周期差分に変えてからは Kd を大きく取る必要があり、既定（Kp 2 / Kd 10）でまともに追従するのは直線だけです。 S字・円弧・90度コーナーはゲインを上げないとラインを外れます。

形状ゲインの例RMS ずれ備考

開始位置

名前つきの位置は public/config/course/<年度>/robot.yaml の initial_position をそのまま読んでいます。本体シミュレータの 「開始位置」と同じものです。難所だけを何度も試したいときは、そこに位置を足してください。
数値を直に打っても変えられます。「クリックで置く」を押してから軌跡の上を 押すとその場所へ、押したまま動かすと向きも決まります（Shift を押しながらでも同じ）。

モータモデル（エンコーダ）

本体（src/Sensor/SorotMotor.js の getCount）は遅れを持ちません。 PWM にそのまま比例してカウントが増えるだけで、 count += 0.01 × PWM × max_speed です。実機で詰めたシナリオを 再現したいときはこちら。
ビジュアライザの模型は慣性と摩擦を持ち、PID の遅れが軌跡に出ます。 Kp / Kd を動かしたときの振動やオーバーシュートを見たいときはこちら。 どちらで走るかで速さも応答も大きく変わるので、ゲインは模型ごとに取り直してください。 下の表のゲインはビジュアライザの模型で測ったものです。 「走らせ方」をシナリオにすると、本体と同じ模型へ自動で切り替えます。

ω += Ts × (α·u − β·ω − J·τc·sign(ω) − J·τload)
θ += Ts × ω  /  エンコーダ値 = floor(θ)
現在値: θ = 0 / ω = 0
